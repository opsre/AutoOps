1.3 执行摘要

天枢 AutoOps v4 是一个单体式、前后端分离、功能密度极高的企业级运维平台。它试图用一个 Go 进程 + 一个 Vue SPA 覆盖传统主机运维（CMDB、堡垒机、SSH 终端、脚本作业）、云原生运维（多集群 K8s 全资源控制台、Arthas 诊断）、数据运维（MySQL/PgSQL/Redis/MongoDB/ES 统一管理与 SQL 审计）、可观测性（Prometheus 告警引擎、探针、SNMP、域名/SSL/API 拨测、云账单）以及 AI 运维助手，并辅以 RBAC、审计录像、License 授权等企业特性。

最突出的三项优势

  • 功能广度罕见：12 个业务域、761 条接口，K8s 单模块即 159 条路由，覆盖节点/工作负载/网络/存储/YAML/日志流/容器终端/Arthas。
  • 闭环能力强：资产 → 凭据 → 作业 → 监控 → 告警 → 审计形成数据链，例如 CMDB 主机可被探针部署、任务执行、堡垒机授权、Prometheus 图表共同引用。
  • 自研深度足够：Redis 优先级任务队列、探针源码生成与交叉编译下发、Guacamole 协议代理、ANTLR SQL 解析器、模型签名增量迁移，均非简单 CRUD 拼装。

最需要注意的三项约束

  • 完成度参差：AI 决策引擎为 TODO stub、知识库未接线、API 监控告警未发通知、部分前端流程库声明未使用。
  • 安全基线偏弱：JWT 密钥与 AES 密钥硬编码、配置含明文口令、后端无接口级 RBAC 与限流、CORS 全开。
  • 工程一致性问题：SQL 脚本与自动迁移表名不一致、AI 相关两套 Agent 概念混用、Swagger 覆盖率不足、生产 Nginx 代理配置缺失。
总体判断：v4 已达到「功能演示 / 中小规模内部平台可用」的水准，具备很好的二次开发骨架；若用于生产或对客交付，建议先完成第 08 章列出的 P0 安全整改与 P1 功能闭环，再补齐自动化回归与文档。

4.4 三层权限控制

路由级

router.beforeEach 仅校验 token 与 sysAdmin 是否存在，未登录跳 /login；不按角色动态过滤路由。

菜单级

后端登录响应下发 leftMenuList，前端只负责渲染；无权限菜单不出现在响应中，是主要的页面可见性控制。

按钮级

自定义指令 v-authority，策略为「可见但禁用」：置灰 + 拦截点击并提示「没有该操作权限」。

后端侧：jwtGroup 统一挂载 AuthMiddleware + LicenseMiddleware + LogMiddleware，但 AuthMiddleware 只验证 JWT 签名与有效期，不校验角色/菜单权限；权限判定散落在业务代码中（如服务上线工单的操作权限、堡垒机主机授权）。db 模块例外：由 db.InitDbRouter(router) 自行建组挂载鉴权，不受 LicenseMiddleware 约束。

前端 src/utils/request.js 的请求拦截器会给所有非 /api/v1 开头的 URL 自动补前缀并注入 Bearer Token；响应 401/406 清 storage 跳登录。开发环境 vue.config.js 配置 /api/v1 → http://127.0.0.1:8000 代理并开启 WebSocket 透传，不做 pathRewrite。

09

结论

适用场景、总体评价与二次开发建议

天枢 AutoOps v4 的价值不在于某一项技术做到极致，而在于把运维日常需要的十几个系统压进同一个进程和同一套资产模型。533 个 Go 文件、761 条接口、64 张表构成的骨架里，CMDB、K8s、数据库、任务、监控告警五个域都达到了「功能完整、可直接演示、可继续开发」的水准；Jenkins 发布与工单审批、SSH 会话录像、探针自动编译下发、Arthas 集成等属于同类开源项目中较少见的深度实现。

另一方面，v4 明显带着「快速迭代堆叠」的痕迹：AI 域只有接入层和单点分析真正跑通，决策引擎、知识库、API 告警仍是占位；安全基线停留在「能用」而非「可交付」；SQL 脚本、环境变量、流程库、Swagger 文档都存在未收敛的残留。它更像一个功能丰富的二次开发起点，而不是开箱即用的生产级平台。

适合

中小企业混合环境（VM + K8s）统一运维入口；内部工具整合与 POC 演示；有 Go/Vue 团队、希望以开源代码为骨架定制的场景。

需评估

对合规、审计、权限隔离要求严格的行业；大规模多集群生产托管；需要 HA / 多租户 / 完整 AIOps 闭环的场景。

建议路径

先按第 08 章阶段一完成安全整改，再以 CMDB → 任务 → 监控 为主链打通回归测试，最后决定是否投入 AI 域的完整重构。

与主线版本的关系：仓库 README 已指向 v5.0 镜像与 VictoriaMetrics / Kafka / Vector 等新组件，v4 是 2026-09-17 的源码快照。若目标是评估「当前可用版本」，建议同时拉取主线最新代码做差异比对；若目标是学习架构与复用模块，v4 的完整源码已经足够。
